# Generate OpenAPI - EPA Digital Standard

Generate and maintain OpenAPI/Swagger documentation for Go APIs.

## What This Skill Does

1. ✅ Analyzes Go handlers for OpenAPI comments
2. ✅ Generates or updates docs/swagger.json
3. ✅ Exports to Postman format (JSON collection)
4. ✅ Validates spec against handlers (consistency check)
5. ✅ Detects missing documentation
6. ✅ Uploads to Postman workspace (optional)

## Prerequisites

Ensure you have:
- `swag` CLI installed: `go install github.com/swaggo/swag/cmd/swag@latest`
- Go API with handlers that have OpenAPI comments
- Current working directory is the Go API root

## Inputs

Ask the user for:

- **Continue with current directory?** (Y/n)
  - Or: **Path to Go API** (if not current directory)
- **Export to Postman?** (Y/n)
  - If yes: **Postman API Key** (optional, for auto-upload)

## OpenAPI Comment Format

Handler methods should have OpenAPI comments:

```go
// @Summary Create a new user
// @Description Create user with email and password
// @Tags users
// @Accept json
// @Produce json
// @Param body body CreateUserRequest true "User data"
// @Success 201 {object} UserResponse
// @Failure 400 {object} ErrorResponse
// @Router /users [post]
func (h *UserHandler) Create(w http.ResponseWriter, r *http.Request) {
    // Implementation
}

// @Summary Get user by ID
// @Description Retrieve user details
// @Tags users
// @Produce json
// @Param id path string true "User ID"
// @Success 200 {object} UserResponse
// @Failure 404 {object} ErrorResponse
// @Router /users/{id} [get]
func (h *UserHandler) GetByID(w http.ResponseWriter, r *http.Request) {
    // Implementation
}
```

## Workflow

```
1. Validate Go API structure
   ├─ Check for main.go
   ├─ Check for go.mod
   └─ Locate handler files

2. Analyze handlers
   ├─ Find all @Router comments
   ├─ Extract endpoints and methods
   ├─ Check documentation completeness
   └─ Warn about missing comments

3. Generate OpenAPI
   ├─ Run: swag init -g cmd/api/main.go
   ├─ Parse docs/swagger.json
   ├─ Add EPA Digital metadata
   └─ Validate against Swagger 3.0 spec

4. Create Postman collection
   ├─ Convert OpenAPI → Postman format
   ├─ Add authentication headers
   ├─ Add environment variables
   └─ Export postman_collection.json

5. Validation
   ├─ Check all endpoints have descriptions
   ├─ Check all endpoints have status codes
   ├─ Verify parameter types
   └─ Generate report

6. (Optional) Upload to Postman
   └─ Create workspace collection
   └─ Sync with API key
```

## Generated Files

```
docs/
├── swagger.json         ← OpenAPI spec (generated by swag)
├── swagger.yaml         ← YAML version
└── postman_collection.json  ← Postman collection
```

## Using the Generated Files

### View in Swagger UI
```bash
# Option 1: Local (requires swagger-ui docker)
docker run -p 8080:8080 \\
  -e SWAGGER_JSON=/foo/swagger.json \\
  -v $(pwd)/docs:/foo \\
  swaggerapi/swagger-ui

# Access: http://localhost:8080
```

### Use in Postman
1. Download desktop Postman (or use web version)
2. Import `postman_collection.json`
3. Set environment variables:
   ```json
   {
     "base_url": "http://localhost:8080/api/v1",
     "api_key": "your-api-key"
   }
   ```
4. Test endpoints with Postman

### Share with Team
1. Commit `docs/swagger.json` to repo
2. Share `docs/postman_collection.json` via Postman workspace
3. Or: Upload to swaggerhub.com (free tier)

## Tips

1. **Add comments to all handlers**
   - Even simple endpoints need @Summary
   - Always include @Tags for organization

2. **Use meaningful descriptions**
   ```go
   // ✅ Good
   // @Description Create a new user with email verification

   // ❌ Bad
   // @Description Create user
   ```

3. **Document error cases**
   ```go
   // @Failure 409 {object} ErrorResponse "Email already exists"
   // @Failure 422 {object} ErrorResponse "Invalid email format"
   ```

4. **Test before committing**
   ```bash
   swag init -g cmd/api/main.go
   # Check docs/swagger.json was created
   # Review it visually
   ```
